# Tuno Windows 界面与交互重做方案

2026-09-25 重新对照 Android 源码、已留存的手机截图和 Windows 当前实现。本文是下一轮实施依据；此轮只做差异审查与方案整理，没有修改播放器代码。

## 对照依据

- Android：`activity_main.xml`、`activity_track.xml`、`TrackActivity.kt`、`SyncedLyricsView.kt`、`FullscreenLyricsController.kt`、`activity_settings.xml`、`activity_equalizer.xml`。已留存的 `.migration/check-home.png`、`wave-done.png`、`lyrics-open.png` 显示首页、播放和全屏歌词状态。
- Windows：`Tuno.PlaybackProbe/MainWindow.xaml` 与 `MainWindow.xaml.cs`。当前窗口可启动，但本次桌面截图抓取失败，因此视觉判断以 XAML 结构为准；后续实施须补真实窗口逐页截图和动态录屏。
- 对齐目标是同一产品的页面层级、视觉重心、操作反馈和功能语义；鼠标、键盘与触控板按 Windows 习惯适配，不机械复制手机坐标。

## 已确认的主要差异

| 环节 | Android 当前行为 | Windows 当前行为 | 重做要求 |
|---|---|---|---|
| 首页骨架 | 顶部搜索/排序/设置/菜单，下面是“我的音乐”入口、音乐/歌单切换、专辑/艺术家/文件夹快捷入口、封面歌曲卡片，底部迷你播放器 | 固定 212 px 左侧栏、工具按钮区和列式 DataGrid，底部工具条 | 重新组织信息架构：顶部命令栏 + 音乐主页 + 卡片式内容 + 悬浮播放器；移除旧侧栏与表格作为默认主页 |
| 播放页 | 大封面是主角，下方歌曲信息、波形进度与圆形播放控制，封面主色延伸到背景 | 宽屏“封面左/歌词右”双栏，实际进度仍在全局底栏的普通 Slider | 改为独立沉浸播放状态，封面/标题/波形/核心控制居中，队列作为次级抽屉或切换面板 |
| 进入与切歌 | 歌曲封面共享元素展开/收回；相邻页与波形预备好后随手势移动、回弹或完成切歌 | 打开面板只有 220 ms 淡入/缩放；切歌直接替换文字与封面，鼠标手势只在松手后执行 | 建立可中断的连续转场，预取前后曲封面与波形；播放指令先执行，视觉异步跟随 |
| 全屏歌词 | 上滑封面时封面缩到左上角，歌词接管主体，底部精简播放栏；可反向拖回 | 另一个 ListBox 面板显隐，加同一套淡入动画 | 在播放页内部做可拖拽的“播放/歌词”状态变换，保留歌曲与播放器实例 |
| 歌词跟随 | 当前句居中、平滑滚动、上下渐隐、当前句亮白加粗并轻微放大；手动浏览暂停跟随，4.5 秒后恢复，也可立即点“回到当前句” | 200 ms 轮询；仅在句子变化时调用 `ScrollIntoView`，只能保证可见而非居中；滚轮后一直保持浏览状态直到手动恢复 | 统一歌词状态机：自动跟随/手动浏览/定位中；按句子中心平滑定位，手动滚动后定时恢复，切歌和跳转时取消旧动画 |
| 设置与均衡器 | 设置是常规选项页；均衡器是独立页面，含预设与频段 | “设置与播放工具”同一个长页内含均衡器；两个入口都调用 `OpenSettings`，只滚到不同卡片 | 保留设置页，均衡器改为真正独立的调音台页面；入口、返回路径和视觉层级清楚 |
| 睡眠定时 | Android 菜单仍有此项 | Windows 侧栏和设置页均有入口 | 按用户要求从 Windows 产品界面及运行逻辑移除，不再列为对齐目标 |
| 按钮反馈 | Android 有状态高亮、菜单/弹窗转场和播放状态变化 | 多数按钮只切换文字或可见性，缺少进入、关闭和内容衔接 | 定义按钮按下、选中、加载、成功及页面切换的统一动效；避免全页统一淡入掩盖内容变化 |

## 新版页面结构

1. **音乐主页**：顶部单行放搜索、排序、设置和菜单；主视觉为“我的音乐”玻璃面板，音乐/歌单切换位于其中，专辑/艺术家/文件夹作为快捷分类。歌曲使用带封面的双行卡片；多选、收藏和歌单操作放在随选择出现的操作条或右键菜单。底部保留悬浮迷你播放器。宽屏增大留白和内容宽度，窄窗口压缩为单列；不恢复旧式左侧栏与 DataGrid 主页。
2. **播放页**：封面、歌曲名、歌手、波形进度、上一首/播放/下一首、随机/倍速/循环、下一首预览形成一条清楚的视觉主线。背景从封面取色并保留磨砂层次。队列从右侧抽屉进入；歌词入口在封面/波形附近可发现。
3. **全屏歌词**：与播放页共用当前歌曲状态。封面从大图缩到页首；歌词占中间主区域；底部保留小封面、歌名和播放/暂停。点页首封面、返回键或反向手势回播放页；歌词正文滚动仅用于阅读，不触发退出。
4. **设置与均衡器**：设置仅放音乐库/显示/导航/排除文件夹/语言等选项。均衡器独立展示启用、预设、频段和重置；标题与返回清晰。倍速主要放播放页，设置页不重复。删除睡眠定时入口、卡片、计时器处理和相关说明。

## 动效与状态规则

- 共享封面：从实际点击的歌曲卡片或底部迷你封面位置展开到播放页，返回时反向落回来源；来源滚出屏幕时落到迷你播放器。连续点击可取消旧动画并落到最后一次目标。
- 切歌：前后曲封面、标题、背景色和波形提前准备；拖动时跟随指针/触控板，松手根据距离与速度完成或回弹。页面移动与背景/波形过渡共用同一进度；新曲音频立即切换，封面加载慢时保留稳定占位。
- 歌词：播放时间更新高亮；只在活动句变化时启动居中动画，用户滚轮/拖动进入“手动浏览”；4.5 秒无操作或点“回到当前句”恢复。点击有时间戳的歌词跳转并重新定位；无时间轴文本可阅读但不可跳转。暂停、切歌、窗口缩放和无歌词状态都要明确处理。
- 按钮与页面：点击给出短暂压缩/亮度反馈；选中态持续可见；菜单、抽屉和弹窗按出现方向进出；队列与歌词切换、设置与均衡器返回要有对应的反向衔接。动效约 180–350 ms，并尊重 Windows“减少动画”设置。
- 动画只改变渲染状态，不阻塞播放、搜索和扫描。封面/波形解码放后台；视图离开或歌曲变化时取消过期结果。

## 实施顺序与验收

1. **已完成：删减与结构准备**：移除 Windows 睡眠定时入口、卡片和计时器逻辑；设置页只保留常规选项，均衡器为独立工作台；页面切换、返回目标和当前通用进入动效移至 `DesktopNavigation`。隔离输出目录构建通过（0 警告、0 错误），播放、媒体库和歌词 smoke test 均通过；实际启动窗口后，用 UI 自动化点击验证了设置页与均衡器内容互斥，且睡眠定时入口不存在。
2. **已完成：重做主页**：移除固定侧栏与列式 DataGrid 默认主页，改为顶部搜索/排序/设置/均衡器命令栏、“我的音乐”玻璃总览、音乐/歌单切换、专辑/艺术家/文件夹/收藏快捷入口、封面双行歌曲卡片，以及选中后出现的歌曲操作条。分类和歌单使用主页内状态切换，底部播放器继续保留。Step2 构建通过（0 警告、0 错误）；播放、媒体库与歌词 smoke test 通过。真实窗口通过 UI 自动化验证了主页区域、音乐/歌单切换、分类导航、两首测试歌曲卡片、选择后操作条及播放页跳转。
3. **已完成初版：重做播放页与切歌**：播放页已按 Android 的内容顺序重组为大封面、歌曲信息、当前歌词、波形进度、圆形核心控制、随机/倍速/循环和下一首预览；背景继续从封面取色。左右拖动时当前页和相邻歌曲页会跟随指针，距离不足回弹，超过阈值完成切换；按钮切歌使用同一转场。波形支持点击跳转，并与播放进度、时间、暂停状态同步。Step3 构建通过（0 警告、0 错误），播放、媒体库和歌词 smoke test 均通过；真实窗口已成功启动且保持响应。当前桌面会话没有暴露原生窗口给 Computer Use，因此本轮没有取得可核对的窗口截图或自动点击证据，视觉手感仍需在用户可见窗口中确认。波形目前按歌曲生成稳定的视觉包络，不是 Android 端解码音频得到的真实包络；真实波形解码留到细节统一阶段。
4. **重做歌词与队列**：完成上滑/按钮进入全屏歌词、平滑居中/渐隐/手动浏览恢复/点句跳转及队列抽屉。验收：用带 LRC 与无歌词文件逐项录屏检查；歌词不抢切歌手势，队列重排不打断当前曲。
5. **统一细节并实机验收**：逐一检查按钮、菜单、对话框、设置子页的进入/退出和状态；用真实 Windows 窗口在常见窗口尺寸、高 DPI、鼠标与触控板下观察动态，再跑构建、媒体库、歌词和播放回归。

任何“完成”的结论都以真实窗口的逐页截图和关键交互录屏为依据；当前通过构建与 smoke test 只能证明功能路径，不证明布局和动画已达到 Android 的体验。
